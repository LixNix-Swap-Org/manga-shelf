## 1. Project overview & tech stack

* **Purpose:** Self-hosted manga management for one household: series and volumes (incl. box sets, special editions, specials), ownership and reading state per person, shopping list with in-store scanning, release radar with the Manga Passion calendar, wishlist series, anime tab, statistics, trash, backups.
* **Architecture:** A domain core (`core/`) holds every domain endpoint as a pure handler. The server (Express) mounts them through `routes/core.js` and only adds server concerns (sessions, backups as ZIP, uploads via multer, rate limits, system page). The same handlers run on the device in the apps without a server (sql.js). The server delivers the built React frontend under `/`.
* **Operating modes:** browser against the server (PWA), desktop app (Electron: local, as a client or as a server), Android/iPhone app (Capacitor: with or without a server), headless server as a binary (Node SEA, service for systemd/launchd/Windows), Docker image, Pterodactyl ZIP.
* **Backend:**
  * **Runtime:** Node.js >= 22.13 (`node:sqlite` without a flag only from 22.13; `engines` in `package.json`). Docker image `node:22.x-alpine3.x` (pinned, Dependabot keeps it current), Pterodactyl egg `yolks:nodejs_22`, CI matrix 22.13.0 / 22 / 24, SEA binaries with Node 26, desktop with Electron 44 (Node 24).
  * **Framework:** Express 5 (`index.js`).
  * **Database:** SQLite (`manga.db`, WAL) via `node:sqlite` (`db.js`); `better-sqlite3` is only loaded as an optional fallback and is **not** a dependency. Schema and migrations in `core/schema.js`.
  * **Auth:** JWT as the `httpOnly` cookie `token` (browser) or `Authorization: Bearer` (apps); passwords with `bcryptjs`. User and role are loaded from the DB on **every** request (`middleware/auth.js`), not from the token.
  * **Files:** `multer` for images and backup ZIPs; uploads live in `<DATA_DIR>/uploads/`.
  * **Backups:** `archiver` for writing (`services/backupArchive.js`: zlib level 6, images uncompressed, `manifest.json` in every archive), a streaming reader of its own (`zlib`) for restoring. `adm-zip` only writes the small pre-migration backup in `db.js` and reads ZIPs in tests.
* **Frontend:**
  * **Tooling:** Vite 7 + React 18 (`frontend/`), tests with Vitest 5 + Testing Library + jsdom.
  * **Styling:** Tailwind CSS 3, lucide-react 1.x, self-hosted Plus Jakarta Sans font (`frontend/src/fonts/`), custom CSS in `frontend/src/index.css`.
  * **Routing:** `react-router-dom` v7 (`BrowserRouter`; routes `/`, `/manga/:id`, `/login`, in the app build also `/server` and `/lokal`).
  * **Two builds:** web build (`npm run build` → `frontend/dist`, service worker, delivered by the server) and app build (`npm run build:app` = `vite build --mode app` → `frontend/dist-app`, `base: './'`, CSP meta, with the core for standalone mode).
* **Deployment:** Pterodactyl (egg `egg-manga-shelf.json` + ZIP), Docker/Compose (`ghcr.io/lixnix-swap-org/manga-shelf`), server binary or `.deb`/`.rpm`, desktop installers. Reverse proxy (nginx, Caddy, Cloudflare): `trust proxy` comes from `TRUST_PROXY` (default `loopback`, see Gotcha 3).

## 3. Database schema & data models (`core/schema.js`, connection in `db.js`)

The database lives in `<DATA_DIR>/manga.db` (default `./data`). `core/schema.js` runs on any connection with `prepare`/`exec` (server, in-memory tests, sql.js on the device) and logs via `options.log`.

### Table overview

1. **`users`**
   * `id` (INTEGER, PK), `username` (TEXT, UNIQUE, NOT NULL; additionally the unique index `idx_users_username_nocase` on `username COLLATE NOCASE`, see migration 14), `password_hash`, `role` (`admin`, `editor`, `visitor`, `guest`; default `editor`), `created_at`.
   * `locale` (TEXT, NULL, migration 26): UI language of the account (`core/lib/locales.js` `UI_LOCALES`); NULL = like the device. `default_language` (TEXT NOT NULL DEFAULT `'de'`, migration 26): default language of the editions in the collection (wave I18N-D). New accounts: `locale` NULL.
   * `password_changed_at` (INTEGER, ms, migration 9) is also the **session version**: every JWT carries it as `pv` and is valid only while it is unchanged. New values are strictly increasing (`max(now, old + 1)`); a password change, an admin reset, a restore and "Alle Sitzungen beenden" raise it.
2. **`mangas`**
   * `id`, `title` (NOT NULL), `alt_title`, `author`, `publisher` (normalised, see `publisher_aliases`), `language`, `description`, `cover_image`, `banner_image` (`/uploads/<name>` or a foreign URL), `created_at`, `updated_at`, `updated_by` (FK `users.id`).
   * **Editions** (migration 27, wave I18N-D): a series is one edition in one language. `language` is an ISO 639-1 code (`de`, `en`, `ja`; names and BCP-47 tags are normalised on every write by `core/lib/language.js`, also in the CSV import and the trash restore; an unknown name or a two-letter code outside ISO 639-1 (`xx`) is 400 `LANGUAGE_INVALID`; empty = the caller's `users.default_language`); `region` (TEXT, NULL; ISO 3166-1 alpha-2 upper case, a BCP-47 tag such as `en-US` fills it); `work_key` (TEXT, NULL, index `idx_mangas_work_key`): editions of one work share it (`anilist:<id>`, `mal:<id>`, `manual:<24 hex>`; a manual key is random, made only by `POST /mangas/:id/editions`, `PUT /mangas/:id/work`, the CSV import (one fresh key per manual key of the file) and the seeder (derived from the seed), never derived from a series id, so an unlinked series never rejoins its old group); `currency` (TEXT NOT NULL DEFAULT `'EUR'`; ISO 4217 upper case): the prices of the series and all its volumes. Money totals (statistics, shopping list, radar) add only `EUR` series, other currencies are listed apart, never converted. `editions` in the detail is computed from `work_key`, never stored.
   * `status` – publication status according to the publisher: `Laufend`, `Abgeschlossen`, `Pausiert`, `Abgebrochen`, `Geplant` (`MANGA_STATUSES` in `core/lib/validate.js`; `Unbekannt` from Manga Passion is stored as `Laufend`). Older rows can carry other values; `PUT` lets an old value through when it is sent back unchanged.
   * `tags` – comma-separated text, normalised on save ("Abenteuer, Fantasy", `core/lib/tags.js`).
   * `total_volumes` (INTEGER, NULL) – known total volume count 1–5000; `''`, `null` and `0` clear it (`parseTotalVolumes`).
   * `owned_volumes` (INTEGER, DEFAULT 0) – number of volumes with status `Vorhanden`, maintained by SQLite triggers (migration 16). Never set it by hand; `PUT /api/mangas/:id` ignores the field.
   * `manga_passion_id` (INTEGER, NULL) – linked German Manga Passion edition (index `idx_mangas_passion_id`), set automatically only for an unambiguous match (Case K); only a `de` series keeps one (`POST`/`PUT /api/mangas` store NULL for another language, a `PUT` away from `de` clears it); `manga_passion_edition_data` (TEXT, legacy field, in no answer any more).
   * `wish_priority` (INTEGER, NULL, migration 17) – wishlist series: NULL = not wished, otherwise 0–3 like `volumes.priority`. A series is a **wishlist series** while the field is set and no volume is `Vorhanden` (`wished` in `GET /api/mangas`). Not coupled to `status`.
   * `collecting` (TEXT NOT NULL DEFAULT `'aktiv'`, migration 20) – collecting status of the household: `aktiv`, `pausiert`, `abgebrochen` (Gotcha 33).
3. **`volumes`**
   * `id`, `manga_id` (FK, ON DELETE CASCADE), `volume_number` (TEXT, NOT NULL: "1", "0", "12.5", "Schuber 3", "Artbook"; regular volumes without the "Band " prefix), `type` (`volume`, `special_edition`, `schuber`, `special`; default `volume`), `status` (`VOLUME_STATUSES`: `Vorhanden`, `Fehlt`, `Vorbestellt`, `Erscheint bald`, `Bestellt`), `isbn` (normalised, index `idx_volumes_isbn`), `price`, `target_price` (target price), `priority` (0–3, wish priority for `Fehlt`), `release_date` (`JJJJ`, `JJJJ-MM` or `JJJJ-MM-TT`, i.e. YYYY, YYYY-MM or YYYY-MM-DD), `release_year`, `purchase_date`, `condition`, `pages`, `publisher` (only a differing volume publisher), `notes`, `cover_image`, `images` (JSON array), `manga_passion_volume_id` (linked MP volume), `created_at`.
   * `language` (TEXT, NULL, migration 27): the volume's own ISO 639-1 code (an English volume in a German series); NULL = the series language. The **effective language** is `COALESCE(v.language, m.language)` (frontend `volumeLanguage()`); prices stay in the series currency.
   * `number_sort` (REAL, NULL, migration 15) – numeric value of the volume number ("Band 12" = 12, "12.5" = 12.5, labels = NULL), maintained by triggers, index `idx_volumes_manga_number (manga_id, type, number_sort)`. **Rule:** never put volume number logic into SQL via `CAST`/`GLOB`, always use `core/lib/volumeNumber.js` (`regularNumberedSql`, `volumeOrderSql`). The column is internal and appears in no answer.
   * `purchase_date` of the volume: the first purchase through the ownership route fills it (never overwrites); when one owner gives the volume up and others remain, the earliest purchase date of the remaining owners applies (`purchaseDateFromRemainingOwners`); when the last one gives it up, it is cleared.
4. **`volume_reads`** – reading state **per user**: `volume_id`, `user_id` (both FK, CASCADE), `read_at`; PK (`volume_id`, `user_id`). Read entries survive when a volume is given up and count again as soon as it is owned again. "Gelesen" (read) is **not** a status.
5. **`volume_owners`** (migration 11) – ownership per user: `volume_id`, `user_id` (PK together, CASCADE), `price`, `purchase_date`, `condition`, `created_at`. `volumes.status = 'Vorhanden'` means "at least one owner"; `core/lib/owners.js` keeps both in sync (status Vorhanden without an owner → the acting user becomes the owner; status ≠ Vorhanden → every owner is dropped; last owner gone → `Fehlt`). Owner lists are sorted by `created_at, rowid` everywhere. `volume_owners.price` is a snapshot without an editor; statistics use `volumes.price`. When `PUT /api/volumes/:id` changes the price, purchase date or condition, owner rows holding the old volume value take over the new one. When a user is deleted, their sole ownerships go to the deleting admin.
6. **`app_settings`** – `key`/`value`: `collection_start_date` (new databases without an entry: `derivedStartDate()` in `core/handlers/stats.js` takes the earliest purchase date – a bare year from 1 January, a month from the 1st – or the earliest creation date of a series or volume, otherwise today; older databases lose the old default `2021-04-09` through migration 24 unless a volume was bought or created before it; a date chosen by hand stays; `PUT /api/stats/settings` with `null` or `''` deletes the entry), `instance_id` (UUID of the instance, travels with the database), `revoked_sessions` (tokens blocked by logout until they expire, max. 5000), `calendar_feed:<sha256>` (calendar feeds, Case R), `uploads_metadata_stripped`, `anime_refresh_day`, `sources_notice_shown`. An old `jwt_secret` entry is deleted at startup (Gotcha 6).
7. **`manga_passion_cache`** – `cache_key` (e.g. `releases_2026_10`, `mp_search_q_<query>`, `mp_edition_vols_<id>`, `mp_edition_info_<id>`), `json_data`, `created_at` (Unix time, 12 h cache).
8. **`animes`**, **`anime_progress`**, **`api_cache`** (migration 18) – anime entries shared by everyone (`anilist_id`/`mal_id` UNIQUE, both NULL = manual entry; metadata snapshot, `manga_id` ON DELETE SET NULL, `next_check_at`), progress per user (`status` Geplant|Schaue|Gesehen|Pausiert|Abgebrochen, `episodes_watched`, `score` 1–10, `started_at`/`finished_at` in `APP_TIMEZONE`) and the answer cache of the sources (`expires_at`).
   * `anime_progress.resume_url`/`resume_episode` (migration 25): resume link from a shared episode link (always canonical) and the episode it points to; any other change of `episodes_watched` (`PUT …/progress`, +1) clears both.
   * `animes.external_links`/`streaming_episodes` (migration 25, JSON): AniList `externalLinks { site url type }` and `streamingEpisodes { title url site episode }` (http → https, episode from "Episode N"); both in `KEEP_WHEN_EMPTY` and only overwritten by AniList (Gotcha 29).
   * **`anime_links`** (migration 25): remembered service link per entry: `anime_id` (CASCADE), `service`, `external_id` (Crunchyroll series ID), `url`, `created_at`; unique per (`anime_id`, `service`), (`service`, `external_id`) deliberately not unique (one Crunchyroll series spans several AniList seasons).
     * **Season links** (wave W2, no migration, `service` has no CHECK): next to the series link (`service` = service ID) there are rows with `service` = `<service>:season:<season>` and `external_id` = `<SERIES-ID>:<season>` (`seasonLinkOf`/`seasonServiceOf` in `core/watch/crunchyroll.js`). The history sync uses them to map a season to exactly one entry; an entry can carry several seasons (One Piece = one AniList entry, many Crunchyroll seasons) because every season has its own `service`. They are created on confirmation (`remember.season` of `POST …/watched`, moves only this season away from its previous entry) and during the sync when exactly one entry linked through the series or naming it on AniList names the season in its title. `rememberedLinks` and `resolve-link` read only the series link.
   * **`anime_sync`** (migration 25): AniList list sync per user: `user_id` (CASCADE), `service`, `enabled`, `external_user_id` (AniList `Viewer.id` of the current token), `last_synced_at` (ms), `last_error`, `last_report` (JSON `{ pulled, pushed, not_in_list }`), `updated_at`; PK (`user_id`, `service`). It lives in `manga.db` so that it also applies on the device; an import on the device empties the table.
9. **`user_api_credentials`** (migration 19) – own and instance API keys: `user_id` (NULL = instance, admins only), `provider` (`anilist`, `mal`, `google_books`), `secret_enc` (AES-256-GCM, `utils/secretBox.js`), `label`, `last4`, `allow_background`, `last_used_at`/`last_ok_at`/`last_error`; unique over (`COALESCE(user_id, 0)`, `provider`).
10. **`trash`** (migration 21) – trash: `kind` (`manga`|`volume`), `ref_id`, `manga_id`, `title`, `payload` (JSON with the series or volume, volumes, owners, reading state, linked anime), `deleted_by`, `deleted_at`. Deleted rows leave their tables; after 30 days the scheduler deletes them for good.
11. **`publisher_aliases`** (migration 22) – `alias` (lower case, without a trailing "!") → `canonical`. `normalizePublisher` checks this table first, then the built-in list, then the name without its legal form (GmbH, Verlag, Co., KG, AG, mbH). A result that is itself an alias is followed once (also through the built-in list); that is why a merge into a built-in spelling written differently keeps an identity row (`tokyopop` → `Tokyopop`), and migration 23 adds it for older merges.
12. **`schema_migrations`** – `version`, `name`, `applied_at`.

### Migrations

New migrations are **appended** to the array in `migrationList()` in `core/schema.js`; never change shipped migrations. Each runs in its own transaction, and the log names the changed rows and the duration. If one fails, the start aborts; `initDb()` only sets the connection after a successful migration. If migrations are pending at startup and users exist, `db.js` first writes the DB backup `backups/vor-update-v<old>-auf-v<new>-<timestamp>.zip`. If that fails, the start aborts before the first migration with a German message (nothing changed); only `MIGRATE_WITHOUT_SNAPSHOT=1` migrates anyway. Migration 22 rewrites existing publisher spellings (seed aliases and legal-form suffixes of built-in publishers); deleting an alias later does not undo that. The only way back is the `vor-update` backup in the old version (README, "Upgrading from v2.19.1"); an older version on the migrated database writes legacy forms again (e.g. the status "Gelesen") that no migration converts a second time. Restored backups run through the same migrations before the swap (`migrateDbFile()`, without a pre-update backup). Before shipping a new migration, do the dry run against a copy of a real database: `node scripts/migrate-dry-run.js path/to/manga.db` (pending migrations with rows and duration, `integrity_check`, `foreign_key_check`; the original is only opened read-only).

* `initDb()` sets `journal_mode = WAL` and `synchronous = NORMAL` (a crash loses nothing, a power cut at most the last commits).

## 4. Roles, permissions & operating modes

### Roles
* **`admin`:** everything; user management, backups, system page, instance API keys, merging publishers, emptying the trash, collection settings (`PUT /api/stats/settings`, date `YYYY-MM-DD` from 1900, at most one day after today's UTC date). Only admins may change ownership and reading state of **other** users (`user_id`, otherwise 403 `FORBIDDEN`) and enter other owners/readers in a CSV import.
* **`editor`:** create, edit and delete series, volumes and anime (trash); upload images; own ownership and reading state; CSV import; data cleanup.
* **`visitor` / `guest`** (shown everywhere as "Gast"): read only; writing endpoints answer 403 `READ_ONLY`. Guests get CSV as export only.
* The frontend shows roles only through `roleLabel()` (`components/dashboard/dashboardShell.js`) (Admin, Editor, Gast, offline "Offline").
* **Offline mode:** when the server does not answer, the app runs as `{ role: 'visitor', realRole, offline: true }`. Editors and admins may still toggle ownership and reading state (`canToggle` in `MangaDetail.jsx`, `useVolumeActions`, `useDetailKeyboard`); the changes go into the outbox. Creating, editing and deleting stay blocked offline.

### Frontend architecture & operating modes
* **Languages (`frontend/src/i18n/`, waves I18N-A to I18N-C):** 13 UI languages (`LANGUAGES`: de, en, fr, es, it, pt-BR, nl, pl, ja, ko, zh-Hans, ru, tr; the same codes as `UI_LOCALES` in `core/lib/locales.js`), list and steps to add one in Gotcha 38. The German source text is the key (`t('Speichern')`, `tn('Band', 'Bände', n)`, `rich('Angemeldet als {name}', { name: <strong>…</strong> })`, placeholder `{name}`); German needs no catalog, every other language loads `locales/<language>.json` as its own chunk before switching (`LOADERS`, static imports). * **Three transport modes in `utils/api.js`:** `web` (browser from the server, cookie, relative `/api` URLs), `remote` (app with a server: `getApiBase() + path`, `Authorization: Bearer`, `X-Client: app`, `credentials: 'omit'`), `local` (app without a server: `isLocalMode()` = app build and `localStorage.mangashelf_mode === 'local'`; relative `/api/…` paths go to `local/localTransport.js`, the answer is a real `Response`).
* **Standalone mode (app without a server):** `local/runtime.js` opens `manga.db` in sql.js through `core/adapters/sqljs.js`, applies `core/schema.js` unchanged (a server backup is a valid app backup) and calls `dispatch()` from `core/routes.js` with the local profile as `ctx.user` (role always `admin`, no login). The database is saved as a whole 300 ms after every change (browser build: IndexedDB `mangashelf-local`; Capacitor: a real file in `Directory.Data`; Android excludes `manga.db` together with `.new`/`.old`/`.tmp`/`.seq` and `uploads` from cloud backup and device transfer in `backup_rules.xml`/`data_extraction_rules.xml`, test `mobile/test/backupRules.test.js`; iOS still backs up `Directory.Data` via iCloud). The footer shows "Auf diesem Gerät · <profile>" and the save state there (event `mangashelf:local-store`), never the online state or an offline copy. `local/localServer.js` answers the server routes the interface needs (`/auth/me` with `local: true`, `/setup/status`, `/auth/logout`, `/health`, `/users` as profiles, `/upload`, `/upload/multiple`, `/auth/api-keys`, `/admin/api-keys`); everything else that only the server has answers 404 `NOT_AVAILABLE_LOCALLY` "Im Modus ohne Server nicht verfügbar". Uploads are stored as blobs, the database holds `/uploads/<name>` as on the server, `assetUrl()` returns an object URL. External sources are called directly from the device (`ctx.http`); when CORS blocks a call in the browser build, the notice `CORS_BLOCKED` appears once per host, in the apps CapacitorHttp replaces the path. API keys never go into `manga.db` (browser build: IndexedDB with the notice "nicht sicher, nur für Tests", apps: secure storage).
* **Saving on the device** (`local/runtime.js`): a write hook on the connection (`trackWrites`: `prepare().run` with changed rows, `get`/`all` of a writing statement – starts with WITH/INSERT/UPDATE/DELETE/REPLACE or contains RETURNING, e.g. `DELETE … RETURNING` for the bulk "unread" –, `exec` except BEGIN/COMMIT/ROLLBACK/SAVEPOINT/RELEASE) marks the database as changed, also for writes during a GET; as a safety net below that, every writing request compares `SELECT total_changes()` before and after. It is saved 300 ms later, and at once on `pagehide` and `visibilitychange` (hidden). If saving fails, the error stays (`runtime.status().saveError`), saving is retried with backoff (1 s up to 60 s), `flush()` throws, writing requests answer 507 `LOCAL_SAVE_FAILED`, and the app shows a persistent notice until the next successful save; a change that arrived during a retry is saved after that retry succeeds.
* **Two windows:** one window holds the lock `mangashelf-local:manga.db` (`navigator.locks`, `store.lockName`) for its lifetime; another one only reads (writing → 423 `LOCAL_LOCKED`, notice with "Neu laden"), reloads after every save of the other one (BroadcastChannel `saved`) and takes over as soon as the lock is free. A reading window creates no profile: if its profile is missing in the stored database, it counts as provisional (`PENDING_PROFILE_ID` = -1, not remembered as the local profile) and is only created and saved together with the lock; on reload the profile ID only counts while the name (ignoring case) still matches, otherwise the name does. Reopening in the same window (profile switch, `openLocal`) does not release the lock: `resetLocalRuntime()` closes with `close({ keepLock: true })` in standalone mode, the lock waits in `windowLocks` (`local/localTransport.js`) for the next runtime of this window; only after leaving the mode is it released and a waiting window takes over. Without `navigator.locks`, a save counter (`manga.db.seq`) protects the data: an older window never overwrites a newer state (409 `LOCAL_CONFLICT`).
* **Replacing the collection** (importing a backup, "Vom Server holen", `replaceDatabase`): once the profile row is settled and before `prepare` and the first save, `sanitizeImportedDatabase(conn)` (`local/sanitize.js`) runs on every imported database: under `PRAGMA secure_delete = ON` (the old value afterwards) **every** `password_hash` becomes `!local-profile` (including that of the fetching admin; the profile keeps its role), and `user_api_credentials`, `anime_sync` as well as the `app_settings` `calendar_feed:*`, `revoked_sessions` and `jwt_secret` are deleted; a database of the app itself stays unchanged. A ZIP from the app therefore holds no password for any account: restored on a server, `POST /api/backup/inspect` names these accounts (`accounts_without_password`), they need a password reset; "Zusammenführen" (merge) leads into an existing server collection. After that: first write new files (an existing name with different content first as `.incoming-<name>`), then save the database, then switch, finally delete uploads outside the new set; if something fails before that, the old collection stays unchanged (including unsaved changes). While this runs, writing requests (and a second `replaceDatabase`) answer 423 `LOCAL_BUSY` ("Die Sammlung wird gerade ersetzt – bitte gleich noch einmal versuchen."), and nothing more is saved from the old database. Afterwards the window event `mangashelf:local-store` (`replaced`) fires and App reloads (`handleLocalReplaced`, one run per restore). "Backups" in the shelf header passes the same function through (`onLocalReplaced`: App → Dashboard → DashboardHeader → LocalBackupDialog); afterwards the shelf reloads its data and stays on `/`, without an open collection it goes to `/server`. Only the active database fills the publisher aliases (`openDatabase(SQL, bytes, { live: true })`).
* **Cleanup on the device:** the window holding the lock calls `trash.purgeTrash(ctx)` at startup and every 24 hours and deletes uploads nothing refers to any more (columns as in `services/uploadCleanup.js`, trash included). `setLocalAdapters({ store, http, files, secureCredentials })`: with its own `files` (e.g. `urlFor()` via `convertFileSrc`), preloading all uploads as blob URLs is skipped.
* **Outbox in standalone mode:** no outbox sync starts; entries belong to `local:<profile ID>`, `sendEntry` never sends server entries to the device core or the other way round. The device core answers at once and finally: `submitChange` queues nothing there (not even offline), and `classifyOutboxResponse(res, entry)` drops every answer except 2xx/404 (507/423/409, also no answer) as `drop`; the caller takes back the optimistic change and reloads, App shows the persistent notice from the status of the core.
* **Routes in the app build:** without a stored server `/server`; server reachable and token present → collection; otherwise login with the server name. `/lokal` = setup without a server; in standalone mode `/server` shows the `LocalScreen` (profile, sources, backup, takeover, "Modus wechseln") and `/login` redirects there. ## 5. API endpoints (`core/routes.js`, server edge in `routes/*.js`, mounted in `index.js`)

Roles: `public` (no sign-in), `auth` (`requireAuth`), `editor` (`requireEditor`), `admin` (`requireAdmin`). Core endpoints are a row in `core/routes.js` and also run on the device; setup, login, users, API keys, backups, uploads and the system page exist only on the server. `lookup` = per-account limit for external services (shared 30/min, `middleware/userLimits.js`), `remoteImage` = its own limit of 30/min; above that 429 with `Retry-After`. `ETag` = weak ETag with `If-None-Match` → 304 (Gotcha 20).

**Error answers:** every JSON error answer under `/api` has the shape `{ error, code }` (German message, code), for 5xx additionally `ref` (= header `X-Request-Id`, "Fehler-ID" in the frontend). Default codes per status (`BAD_REQUEST`, `NOT_FOUND`, `FORBIDDEN`, `CONFLICT`, `INTERNAL_ERROR`, `SERVICE_UNAVAILABLE`, `INVALID_JSON`, `PAYLOAD_TOO_LARGE`, `UPLOAD_REJECTED` …) and domain codes: `AUTH_REQUIRED`, `SESSION_INVALID`, `READ_ONLY`, `ADMIN_EXISTS`, `SETUP_TOKEN_INVALID`, `INVALID_CREDENTIALS`, `WRONG_PASSWORD`, `TOO_MANY_ATTEMPTS`, `USERNAME_TAKEN`, `CHANGED_MEANWHILE`, `CROSS_ORIGIN`, `VOLUME_DUPLICATE` (with `existing_id`), `NOTES_TOO_LONG`, `EDITION_NOT_CONFIRMED` (`needs_confirmation: true`), `CSV_FORMAT` (with `line`), `DB_REOPENED` (CSV export), `MP_UNAVAILABLE`, `BULK_FIELD`, `BULK_IDS`, `BULK_REVERT`, `BULK_UNDO_FORBIDDEN`, `BULK_UNDO_EXPIRED`, `TRASH_SERIES_MISSING`, `TRASH_ID_TAKEN`, `TRASH_INVALID`, `TOO_MANY_SEARCHES`, `SOURCES_UNAVAILABLE`, `DUPLICATE`, `REFRESH_TOO_SOON`, `UNSUPPORTED_LINK`, `EPISODE_ABOVE_TOTAL` (with `episodes`), `NO_TOKEN`, `TOKEN_REJECTED`, `KEY_FORMAT`, `KEY_REJECTED`, `PROVIDER_UNREACHABLE`, `NO_BACKUP_FILE`, `SCHEMA_NEWER`, `ROLLBACK_COPY_PENDING`, `INSUFFICIENT_SPACE`, `STAGING_NOT_FOUND`, `RESTORE_RUNNING`, `JOB_RUNNING`, `MP_NOT_LINKED`, `MP_EDITION_NOT_FOUND`, `MP_LANGUAGE` (409: Manga Passion action on a series, or a stored volume, whose language is not `de`), `LOCALE_INVALID`, `LANGUAGE_INVALID` (400: unknown language name or a code outside ISO 639-1), `WORK_KEY_INVALID` (400: `work_key` on `POST /api/mangas` other than `anilist:<n>`/`mal:<n>`); on the device only `NOT_AVAILABLE_LOCALLY`, `LOCAL_SAVE_FAILED` (507), `LOCAL_LOCKED` (423), `LOCAL_BUSY` (423), `LOCAL_CONFLICT` (409). Error answers never carry an ETag and always `Cache-Control: no-store`. The server builds **dynamic messages** with `msg('Zu viele Einträge (maximal {max_entries})', { max_entries })` (`core/errors.js`): `error` stays the finished German text, plus `msg` (template) and `params`; the client translates fixed texts by their exact text. A hidden 500 ("Interner Serverfehler") never carries `msg`/`params` (`errorAnswer`, error handler in `index.js`). A cause inside a sentence ("Fehler beim Wiederherstellen: {reason}") is its own message in `params` (`{ msg, params }` or its fixed text). `test/errorContract.test.js` allows no message built by template or concatenation (also not in `msg()` and `CsvFormatError`).

* **Parameters of `msg()`:** the client shows numbers and plain strings unchanged (user data such as titles, entry and file names, volume numbers, paths; API values such as field keys, roles, volume types, providers; formatted sizes). Everything translatable (stored German values such as `Vorhanden`, German job names, German causes) goes into the parameter as a nested `msg('…')` (in the body `{ msg, params }`); lists of allowed German values are built by `msgList(values)` (`core/errors.js`, template `{v0}, {v1}, …`, German text unchanged). A German text fragment as a string parameter is a bug: `test/errorContract.test.js` also checks `db.js`, `notAZip`/`invalidBackup`/`invalidDbFile` and rejects string literals as a `msg()` parameter value or as a `notAZip` detail.
* **Texts in 2xx payloads (`<field>_msg`, wave I18N-D):** a German text in a success answer keeps its field byte for byte and gets a sibling `<field>_msg: { msg, params }`; lists whose entry shape is pinned get a parallel array (`errors_msg`/`warnings_msg` of `POST /api/import/csv`, `warnings_msg` of `POST /api/backup/inspect`, entries `{ msg, params }` or null). Single fields: `message_msg` of `GET /api/lookup/isbn` (not found), the gap check and its `discrepancy`, the autofill misses, the restore answers and `DELETE /api/backups/:filename`; `warning_msg` of `POST /api/backups/create`. Rules in Gotcha 38.

## 6. What has to change where? (task-to-file guide)

### 🔹 Case A: New field for series (e.g. "Demographie")
1. **Database (`core/schema.js`):** add the column to `CREATE TABLE IF NOT EXISTS mangas` **and** append a new migration (check `PRAGMA table_info(mangas)`, then `ALTER TABLE mangas ADD COLUMN …`; the migration itself runs in a transaction, no `BEGIN` of its own). Dry run with `scripts/migrate-dry-run.js`, add the expectation to `test/migrations.test.js`.
2. **Backend (`core/handlers/mangas.js`):** POST and PUT read fields through `readMangaFields`; validate input with parsers from `core/lib/validate.js` (new parsers go there, not into the handler).
   * `GET /api/mangas` (`listMangas` in `core/snapshot.js`) selects the columns **one by one**: enter a new list field there, otherwise it is missing from the overview and the offline copy. The detail view uses `SELECT *`.
   * CSV: add the column to `COLUMNS` (`core/csvExchange.js`, before "Gelesen von") and to the export SELECT (`core/handlers/csv.js`); on import read it in `readSeriesMeta` and write it in `createSeries` (round-trip test in `test/csvExchange.test.js`).

Every new write path that inserts a series sets `language` (the caller's `users.default_language`, or `de` for Manga Passion imports): the calendar matcher and the gap check filter on it. A path that stores `manga_passion_id` stores it only for a `de` series.
3. **Frontend:** `components/modals/AddMangaModal.jsx` (create), `components/detail/MangaHeroCard.jsx` (display + edit form; state and `updateBody` in `hooks/useMangaData.js`, only changed fields are sent). Never derive a manual key from a series id and never accept one from outside: `POST /api/mangas` rejects it (`WORK_KEY_INVALID`), the CSV import remaps it. `editions` in the detail and the offline copy is computed (`loadEditions`/`editionsOf` in `core/snapshot.js`), never stored; the takeover copy skips it as a non-scalar. Frontend: `components/detail/EditionSwitcher.jsx` (falls back to the cached list rows with the same `work_key` when `editions` is missing).

### 🔹 Case H: Backup system & snapshots
1. **Backend (`routes/backups.js`, `services/scheduler.js`, `services/backupArchive.js`):**
   * `createBackupSnapshot(prefix, { includeUploads })` checks the space first (free ≥ 1.2 × (DB + uploads), otherwise 507), copies the DB (`copyDatabaseToTemp()`: `VACUUM INTO` to `data/temp/`, without `jwt_secret`, a partial copy on error is removed together with `-journal/-wal/-shm`), writes `<name>.zip.part` with `manga.db`, `uploads/` and `manifest.json` (app and schema version, category, counters, size and sha256 of the DB), tests the archive (`verifyArchive`: unpack, sha256, open read-only, `quick_check`, counters), writes the sidecar `backups/<name>.json` and only then renames. A snapshot that fails the test stays as "beschädigt" (damaged).
   * **Categories and retention** (per category, sorted by the timestamp in the name): `daily-auto-*` 7 (`BACKUP_KEEP_DAILY`), `manual-*` 10 (`BACKUP_KEEP_MANUAL`), `vor-wiederherstellung-*` 3 (`BACKUP_KEEP_PRE_RESTORE`), `vor-update-*` 3 (`BACKUP_KEEP_PRE_UPDATE`). Only good snapshots are counted; of damaged ones at most the newest stays. Other names are never deleted; a sidecar without `verified` counts as unverified. `holdSnapshot()` holds on to snapshots that were just restored or checked. An invalid value (`30d`, `-1`, `0`) deletes nothing at all (`KEEP_ALL`, a warning on every run).
   * **Daily snapshot:** checked 10 s after startup and hourly afterwards; the backup is made as soon as `BACKUP_HOUR` (default 3) in `BACKUP_TIMEZONE` (default `Europe/Berlin`) is reached and there is no **verified** `daily-auto` snapshot for the day yet. Afterwards `cleanOrphanUploads()`; the run is registered as `lifecycle.trackJob`.
   * **Restore** (`restoreFromZip(path, { allowNewerSchema })`): blocked by a leftover `manga.db.bak` (503 `ROLLBACK_COPY_PENDING`, also after restarts), space check, streaming unpack into `manga.db.restore-tmp` with limits (`RESTORE_MAX_DB_BYTES` 2 GiB, `RESTORE_MAX_UPLOADS_BYTES` 4 GiB, `RESTORE_MAX_ENTRIES` 100 000; unpacked bytes are counted, size and CRC are checked), `validateDbFile` (integrity_check, tables, at least one admin), schema check, `migrateDbFile`, covers to `temp/restore-uploads-*` (only flat image files, metadata stripped). Before the swap `vor-wiederherstellung-<ts>.zip` is created (DB only, must pass the test; sidecar with `referenced_uploads`), and its name comes back as `preRestoreSnapshot`. Then `swapInStagedDb()` synchronously (Gotcha 2), afterwards `persistJwtSecret()`: all earlier sessions end, only the restoring admin gets a new token via `signSessionToken()`.
   * **Two steps:** `POST /api/backup/inspect` stores uploads as `temp/restore-staged-<id>.zip` or holds server snapshots for 15 min; `POST /api/backup/restore/:id` executes. `requireSpaceForUpload` already checks before multer using `Content-Length`. If the client left during the check, nothing is staged.

4. **Network access** always through `utils/api.js` (base + token); images with a server path via `{...assetImgProps(path)}`; downloads via `downloadFile`/`useDownload`/`DownloadLink`, never as a bare `<a href>`.

Replay under `navigator.locks`, first `GET /api/auth/me` (same user only), the stored row is read again before every send (several tabs). Never send toggles directly via `apiFetch`. `utils/volumePatch.js` applies changes optimistically to detail and list (incl. `reader_stats`, `wished`, `collecting`, counters).

### 🔹 Case S: Forgotten admin password / server console
Commands in the Pterodactyl console (stdin of the server, `startConsole()` after the start banner), as a one-shot call `node scripts/admin.js <command>` (exit code 0/1) or as a subcommand of the server binary. The command names are German and stay as they are. Console access is admin access; `ADMIN_CONSOLE=false` switches reading stdin off. In the Docker container always as `node`: `docker exec -it -u node manga-shelf node scripts/admin.js <command>` (otherwise root-owned files appear).

| Command | Aliases | Effect |
| :--- | :--- | :--- |
| `hilfe` | `help`, `?` | list of the commands |
| `status` | – | version, data folder, database, disk space, last backup |
| `backup` | `sichern` | snapshot now (like "Snapshot erstellen") |
| `benutzer` | `users` | every user with their role |
| `passwort-reset` | `reset-password` | `passwort-reset <name>`: 16 characters, ends every session of the user. Shown only on a terminal; otherwise (Pterodactyl console, `docker exec` without `-t`, pipes) written to `<DATA_DIR>/reset-<user>.txt` (0600), only the path is printed. Never logged |
| `admin` | `promote` | `admin <name>`: makes them an admin, only when there is none |
| `rollback-aufraeumen` | `rollback-cleanup` | checks the current `manga.db` and deletes a leftover `manga.db.bak` only with `bestaetigen` |
| `quellen` | `sources` | API keys: state table; `quellen anleitung <anilist\|mal\|google_books>`; `quellen setzen <provider> [--benutzer Name] [--aus-datei path] [--hintergrund]` (asks with hidden input, checks live, stores encrypted; AniList always with `--benutzer`); `quellen entfernen <provider> [--benutzer Name]` |

* New commands with secrets get `{ revealSecrets }` and treat it like `passwort-reset`; `startConsole()` never prints a password.
* The server console buffers lines and runs them one after another; when a command asks for input, it gets the next line (a key pasted along never ends up in the command parser). Unknown commands are echoed with at most 8 characters; for `quellen` only the subcommand is logged, a key on the command line is rejected. In the Pterodactyl console the input is visible; hidden input works with `node scripts/admin.js quellen setzen <provider>` or `--aus-datei`.
* At the first start without instance keys the server prints the hint about `quellen anleitung` once (marker `sources_notice_shown`).
* Tests: `test/console.test.js` (every command and `scripts/admin.js`).

### Environment variables (`utils/config.js`)
A new variable gets an entry in `ENTRIES` (German warning for an invalid value; internal switches `doc: false`), a commented line `# NAME=…` in `.env.example` and a row in the table of README §5 (`test/serverEntry.test.js` and `test/docs.test.js` check this); if Pterodactyl should offer it, also an egg variable (`rules` with `nullable|string`). Start and console commands abort (fail closed) when it is a link, belongs to another account, others can change it (Unix: owner neither our own uid nor root, `g+w`/`o+w`, a data folder with `g+w`/`o+w` that belongs neither to us nor to root, a sticky folder with a foreign `.env`; Windows: owner and every write entry only our own account, Administrators, SYSTEM) or the check cannot run (PowerShell blocked, no SID in the output). `acl.readWindowsSecurity` reads Windows ACLs only as SIDs (`GetAccessRules(…, SecurityIdentifier)`; `parseSecurity` throws on any name); `powershell.exe`, `whoami.exe`, `icacls.exe` and `schtasks.exe` always run with an absolute path from `%SystemRoot%\System32` (`acl.systemTool`). ## 8. Important pitfalls & gotchas (remember these!)

1. **Node.js 25+ warning (`index.js`, first lines):** `DEP0180` (`fs.Stats`) is caught at the top of the file so that the logs stay clean. Do not remove it.
2. **SQLite WAL & restore:** slow steps (unpacking, checking, migrating, the backup before the restore) run asynchronously **before** the swap; other requests keep working on the old DB meanwhile. The swap (`swapInStagedDb`: `closeDb()` with `wal_checkpoint(TRUNCATE)` → `manga.db.bak` via `manga.db.bak.tmp` → `rename` → `initDb()` → `persistJwtSecret()`) is synchronous, without `await`; there is no lock flag or 503 for it. Never replace a file under an open handle (close first, then delete `-wal/-shm`, then replace). If something fails after the swap, it is rolled back; the `.bak` stays after a failed rollback and blocks every restore (503 `ROLLBACK_COPY_PENDING`, also after restarts) until `rollback-aufraeumen bestaetigen` or copying back by hand. `initDb()` does not create a new empty database when `manga.db` is missing/0 bytes and a `.bak` exists (`DB_ROLLBACK_COPY_PENDING`). Only one restore runs at a time (a second one: 409).
3. **Cookies, HTTPS, proxy:**
   * `trust proxy` comes from `TRUST_PROXY` (`utils/trustProxy.js`), default `loopback`: only a proxy on the same host may set the client address via `X-Forwarded-For`. Behind another proxy enter its address, **no hop count**: with `1` anyone who reaches the app port directly picks their own `req.ip`. If nginx/Caddy runs on the host in front of Pterodactyl or Docker, the app sees the Docker gateway: `TRUST_PROXY=loopback, 172.18.0.1` (only the gateway address; Pterodactyl `pterodactyl_nw` = `172.18.0.1`, Docker `docker network inspect <network>` → `Gateway`); plain `loopback` put every visitor into one login limit. **Never the whole subnet** of a shared network: other containers in it (on a Pterodactyl node, other people's servers) reach the container port directly and could choose `X-Forwarded-For` freely. A subnet only for a proxy container in a network of its own in which only the proxy and the app hang. README "HTTPS and reverse proxy", `Caddyfile.example`, `nginx.conf.example` and `.env.example` say the same. The port then has to be reachable only through the proxy (Compose `127.0.0.1:3000:3000` or no `ports:` in the same Docker network; published Docker ports bypass ufw/firewalld; Pterodactyl: allocation on 127.0.0.1). Without a matching setting all clients behind the proxy share one login limit (one-time warning "X-Forwarded-For von … wird ignoriert"). Invalid values end the start ("TRUST_PROXY ungültig").
   * `setAuthCookie` checks `req.secure` and `x-forwarded-proto === 'https'`; over plain HTTP in the LAN the `secure` flag is missing and login works. `COOKIE_SECURE` (`true/1/yes/on/ja`) forces it; with HTTPS `index.js` sends `Strict-Transport-Security`. If the browser does not store the cookie, the login form says so explicitly.
   * **Offline start, app installation, live scanner and shopping offline after a restart only over HTTPS or localhost** (guide in README "HTTPS and reverse proxy") (otherwise browsers do not offer `navigator.serviceWorker` and the camera).
   * **Cross-origin protection** (`middleware/originCheck.js`, before the body parsers): GET/HEAD/OPTIONS pass, `CORS_ORIGIN` origins too; otherwise with `Sec-Fetch-Site` only `same-origin`/`none`, without that header `Origin` has to match the `Host`; without both headers (curl, scripts) the request passes. Requests without a `token` cookie pass with a well-formed bearer or from an app origin. The cookie is detected like cookie-parser does it (never via regex). Reverse proxies have to pass `Host` on unchanged (`proxy_set_header Host $host;`).
   * **CORS:** the bundled frontend uses relative URLs and needs no `CORS_ORIGIN`. `CORS_ORIGIN` entries get credentials, `APP_ORIGINS` CORS **without** credentials (headers Authorization, X-Client, Content-Type, If-None-Match; exposed ETag, X-Request-Id, Retry-After, Content-Disposition). Never mirror other origins.
4. **Directories & frontend delivery:** all persistent data lives under `DATA_DIR` (`manga.db`, `secret.key`, `uploads/`, `backups/`, `temp/`); `data/` is in `.gitignore`. If the data folder is not writable, the server exits with "Datenordner … ist für uid … nicht beschreibbar (z. B. chown 1000:1000 ./data)". The frontend comes from `FRONTEND_DIR`, otherwise `frontend/dist`, then `dist/`; the app directory itself or a directory above it is **never** delivered (compared after `realpathSync.native`, symlinks like `ln -s . dist` are rejected too), `FRONTEND_DIR` may neither contain nor lie inside the app or data directory. Missing files under `/uploads/*` and `/assets/*` as well as every path with a file extension return 404, never `index.html` (client routes have no dot). Precompressed assets (`.br`/`.gz`) are served by a middleware of its own before `express.static`; if a client aborts the download, the callback must not set headers any more. Cache headers: `index.html`, `sw.js`, `manifest.json` always `no-cache` (`utils/staticHeaders.js`), `/assets` one year `immutable`.
5. **Transactions:** there is only **one** SQLite connection. Multi-step writes always through `runTransaction(fn)` from `db.js` or `ctx.db.transaction(fn)` in the core (`BEGIN IMMEDIATE`, rollback on error; `withTransaction` is an old alias), never a raw `BEGIN`. `fn` has to be **synchronous** – never `await` inside it (an async callback is rejected; whatever it does after the first `await` would run outside). Do network I/O (cover downloads) beforehand.
6. **JWT secret & sessions (`middleware/auth.js`):**
   * `JWT_SECRET` is only accepted when it is ≥ 32 characters long and not a placeholder; otherwise the server reads `<DATA_DIR>/secret.key` or creates it (48 random bytes, 0600). Never in the database, so in no backup; an old `app_settings.jwt_secret` is deleted at startup (one-time rotation). File unreadable → the start aborts.
   * Tokens only through `signSessionToken(user)` (contains `pv` = session version, `jti`, `exp`), never `jwt.sign` directly. `requireAuth` rejects when `pv` does not match, the user name no longer fits the ID, `iat` lies more than 60 s in the future or the token was blocked by logout. `tokenFromRequest` reads the cookie first, otherwise `Authorization: Bearer` (the cookie wins; that is why app clients send `credentials: 'omit'`).
   * Writing a password (`PUT /auth/password`, `PUT /users/:id`) after the bcrypt await only via `bumpSessionVersion(id, hash, { username, passwordHash })` in a transaction with the hash read before the await; if the row changed, 409 `CHANGED_MEANWHILE` or 401.
   * `persistJwtSecret()` is the restore hook: deletes a `jwt_secret` from the imported DB, ends every session and empties the logout list.
7. **External downloads, uploads, image metadata:**
   * Every remote image goes through `fetchRemoteImage()` (`utils/safeFetch.js`): only public hosts (DNS checked, every redirect again, IPv6 numerically incl. embedded IPv4; blocked among others 192.0.0.0/24, 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 192.88.99.0/24), 15 MB, 10 s idle and 30 s total timeout, magic byte check. In the core via `ctx.http.fetchImage` + `fetchImage()` from `core/lib/imageCheck.js`. Never `fetch` user URLs directly.
   * `verifyImageUploads` (`middleware/upload.js`) checks local uploads: not an image → every file of the request is removed, 400; wrong extension → renamed; afterwards metadata is stripped (`utils/imageMeta.js`: JPEG without EXIF/XMP/comments/secondary images, the orientation stays as a minimal EXIF block; PNG without text chunks; WebP without EXIF/XMP; GIF/AVIF unchanged), because `/uploads` is delivered without sign-in. The strippers build the result with one allocation; more than 4096 segments or anything unparseable stays unchanged. File names `crypto.randomUUID()`.
   * Restored images run through `stripImageFileSync` (files above 32 MB stay unchanged).
8. **Passwords, rate limits, user names, first setup:**
   * Passwords at least 8 characters (max. 72 bytes, bcrypt). User names max. 64 characters, without `,`, `|` and control characters (`usernameError()`), unique regardless of case (`COLLATE NOCASE` + index from migration 14).
   * `/auth/login`: first `loginGuard.check()` (per account+address after 10, per account after 50 failed attempts in 15 min; addresses that have already signed in successfully are exempt, so nobody can lock the admin out from outside); a blocked request answers 429 without using up the address budget. Then `loginLimiter` (50 failed attempts per 15 min per address, a success is subtracted). The attempt is counted **before** `await bcrypt.compare`. `/setup` 10 per 15 min, `/auth/logout` 30 per 15 min, password change has its own limit per user; an admin password reset lifts locks. Locks are logged with `log.warn`.
   * Counter store (`createWindowStore`): max. 50 000 entries, IPv6 per /64 (a /48 occupies at most 256 keys), IPv4-mapped as IPv4; full → the oldest unlocked entry gives way, an active lock never does; when all are locked, fail open for request limiters, fail closed for `loginGuard`.
   * **First setup:** as long as there is no admin, `POST /api/setup` needs the setup code. Without `SETUP_TOKEN` the server generates a 16-character code (`XXXX-XXXX-XXXX-XXXX`), keeps it only in memory and prints it via `console.log` in the start banner (visible at every `LOG_LEVEL`). Compared via `timingSafeEqual` over SHA-256; case, spaces and hyphens do not matter; no loopback exception. `SETUP_TOKEN` below 12 characters → warning, the generated code applies.
   * The status is validated against `VOLUME_STATUSES` (`core/lib/validate.js`). The legacy value `Gelesen` is accepted as input and stored as `Vorhanden` plus a read entry (`convertLegacyRead`, also before an ownership change), never as a status. If a legacy volume already has read entries, exactly these stay and the substitute owner only becomes the owner; the rule lives in `convertLegacyRead` alone (migration 13, the `legacy_read` fix, ownership changes one by one and in the bulk edit).
9. **Restore – details (`routes/backups.js`):** the ZIP reader reads entries through the open file handle (a snapshot deleted meanwhile does not disturb it); ZIP64 only when the locator really stands before the EOCD. From `uploads/` only flat image files next to the `manga.db` of the archive are taken over (`__MACOSX`, `._*`, HTML/JS are skipped). A backup is fully trusted input (it replaces users and password hashes). On 500 the backup routes only send fixed German texts; invalid archives (not a ZIP, no `manga.db`, broken, not migratable, too large, too many files) return 400.
10. **Configuration only through `utils/config.js`:** the logger, scheduler, radar and console do not read `process.env` themselves either. The getters read on every access (tests may set variables at runtime). `DATA_DIR` has to be set before the first `require('./db')`. Never produce `null` as a retention value (`.slice(null)` deletes everything; invalid = `KEEP_ALL`).
11. **Express 5 & error handling (`index.js`):**
   * The SPA fallback route is the last `app.use((req, res) => …)` (Express 5 knows no bare `'*'`); methods other than GET/HEAD outside `/api` return 404, unknown `/api/*` paths a JSON 404. `req.body` is `{}` without a body (a middleware of its own); `req.query` is read-only, strings always through `qstr()`.
   * Routes have no `try/catch` of their own for the 500 case: thrown errors go to the last error handler, the only place that builds the answer. Expected errors: `throw badRequest('…')`, `notFound('Band')`, `conflict('…', 'CODE', { extra })` (`core/errors.js`, server: `utils/httpError.js`); whoever has to answer themselves (stream already open) uses `sendError(res, status, message, CODE)`. Never `res.status(4xx/5xx).json(...)` directly (static test in `test/hardening.test.js`). A real 500 becomes "Interner Serverfehler" with `ref`; English texts from body-parser, serve-static and multer are translated to German (update `uploadErrorMessage` when an upload limit changes). Never `throw` in a callback outside the request flow (`res.on`, timers).
   * Every error answer (≥ 400, every path) gets `Cache-Control: no-store` and loses ETag/Last-Modified (`uncachedErrors`). The 10 MB parser for `POST /api/import/csv` only runs after `requireEditor`; `cookieParser()` stands before the body parsers for that. The security headers come directly after `compression()` so that 400/413 carry them too.
   * **Security headers:** `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`, CSP (`CONTENT_SECURITY_POLICY`: scripts, styles and fonts only from the own origin, images also `http(s)`, inline styles allowed), `Permissions-Policy` (camera only `self`), `Cross-Origin-Opener-Policy: same-origin`, `X-Request-Id`; `X-Powered-By` off. New external script/API hosts have to go into the CSP.
12. **Offline copy, service worker, session end (frontend):**
   * Offline copy (`utils/offlineStore.js`, IndexedDB `mangashelf-offline`, version 2 with `kv` and `outbox`): last user, series list, every detail from `/api/offline-snapshot` and the ISBN index (`isbn-index`). Sync at startup (3 s after login, then `requestIdleCallback`), in the foreground and via the footer button (throttled to 5 min), never in parallel (`force: true` = exactly one follow-up sync), event `mangashelf:offline-synced`. Afterwards the series covers are preloaded (not on mobile data, 2g/3g, data saver or > 80 % storage; max. 300 covers / 50 MB). `navigator.storage.persist()` after the first sync. `clearOfflineData()` deletes IndexedDB, the shopping list cache and the anime keys (`utils/storageKeys.js`), the outbox stays. After changes in the app the copy is patched (`patchCachedManga`, one transaction) and the ISBN index is discarded (`invalidateIsbnIndex`). In standalone mode `syncOfflineCopy()` does nothing.
   * **Service worker (`frontend/public/sw.js`):** precaches every build file atomically in `mangashelf-app-<version>-<build ID>` (`buildId` in `frontend/vite.config.js`: sha256 over the hashed file names and `index.html`, 12 hex characters; `stampServiceWorker` replaces `__APP_VERSION__` and `__BUILD_ID__`, unstamped `mangashelf-app-<version>`; if a file is missing, the old version stays); the translation catalogs are left out of that list (`catalogFiles`, stamped into `CATALOGS`) and cached on first use, `/manifest.json` and `manifest.<code>.json` likewise through `WARM_LANGUAGE` (Gotcha 38); `/assets/*` cache-first; navigations: network with a 3 s timeout, otherwise the cached page under `/`; a navigation is only stored when every file it names is in the cache. `/uploads/*` cache-first in `mangashelf-uploads-v2` (only real images of the own origin), survives updates. Foreign origins and `/api/` bypass the worker. No automatic `skipWaiting`: `watchServiceWorkerUpdates()` (from `main.jsx` right after `register()`) shows the toast "Neue Version verfügbar" with "Neu laden" (sends `SKIP_WAITING`); `vite:preloadError` → `reloadForStaleChunk()` (not while `navigator.onLine` is false); `AppErrorBoundary` reloads once on a missing chunk.
   * **Startup check** (`App.jsx`): `/api/setup/status` and `/api/auth/me` with a 4 s timeout; without an answer, with an error, with a non-JSON page (captive portal) or a 401 without a code, the app keeps running offline with the stored user and checks again every 30 s and on `online`.
   * **Session end:** only the API client reports it (`SESSION_EXPIRED_EVENT` on a 401 with `AUTH_REQUIRED`/`SESSION_INVALID` from `/api/*`, except login/logout/me/password/setup; `sessionEndAnnounced(res)`). A 401 without a code (auth proxy) never ends the session. App reacts exactly once: delete the offline copy, the list cache (`clearMangaListCache`), the search, the scan list, the view states (`utils/viewState.js`) and the cover cache, abort running downloads, back to `/login`.
   * **Logout:** first `runBeforeLogout()`, then send the outbox, then `POST /api/auth/logout`. If the logout does not arrive, `mangashelf_logout_pending` stays set and is retried before every `/api/auth/me` (browser build; app build: a pending entry per server, Case N). Never leave data readable after signing out (limit: images in the HTTP cache stay).
   * Not available offline: release radar, statistics, editing/creating/deleting.
13. **Logging (`utils/logger.js`):** the backend logs exclusively through `require('../utils/logger').child('name')` (in the core `ctx.log.child('name')`); no `console.*`. An `Error` as an argument is printed with its stack and `err.cause` (recursively, also `AggregateError`) – always pass the object, not `err.message`. The logger never throws (circular → `[Circular]`). 14. **Special editions / gap identity (`core/mangaPassion/`, `core/lib/volumeType.js`, `frontend/src/utils/volumeHelpers.js`):**
   * Collector's/limited editions and box sets carry the same number as the regular volume. Gaps, calendar and autofill match by **type + number**, never by number alone. `classifyOfficialVolume()` reads the API fields first (`specialType 1` = box set, `type 3` = special edition, `type 0` with a number = regular); title words only count when those are missing, and then as whole words (only "schuber" as a partial word). `isSchuberEntry()` is the only box set criterion.
   * Autofill and single lookup map by type (`findOfficialVolume(vols, number, type, { notes, price })`): a regular volume never gets data of a collector's edition; without a matching entry the volume stays unchanged (`matched: false`). A stored `manga_passion_volume_id` takes precedence while type and number match. `matchSchuberVolume` maps "Schuber N" to the N-th box set, distinguishes empty (~12 €) and collector's box sets (> 25 €) and returns `null` for a number the edition does not have.
   * Display names only via `getVolumeDisplayTitle()` / `getEditionLabel()` ("Band" only before a number); `inferVolumeType` exists in `core/lib/volumeType.js` and in the frontend and is kept in sync by `test/specialeditions.test.js`. `mpGapMap` contains only regular volumes; ghosts stand before the special edition of the same name in both sort directions (`buildDisplayVolumeItems`, `getVolumeSortInfo`, `compareVolumesByNumber`) and only appear when the filters allow it (`filtersAllowGaps`).
15. **Manga Passion: client and calendar (`core/mangaPassion/client.js`, `core/mangaPassion/releases.js`):**
   * Only complete answers are cached for 12 h. Incomplete: edition fetch failed, 5xx/timeout, 404 on a later page, more than 20 pages (`MAX_VOLUME_PAGES`), a foreign or repeated `hydra:next`. Then the last stored state (`stale: true`), otherwise `incomplete: true`. Every search query is cached on its own (`mp_search_q_*`, 12 h, empty ones 1 h); after the first network error (or two 5xx/429) the search stops, budget 20 s; without candidates `unavailable: true` → the text "Manga Passion ist gerade nicht erreichbar" (`MP_UNREACHABLE_MESSAGE`), not "Keine passende Edition". `getEditionDetailsAndVolumes` only accepts real edition IDs (`toEditionId`). `is_released` is recomputed from `release_date` on every read. Reused covers (`mp-cov-*`) get a fresh mtime. User agent of the requests: `MangaShelf/<package.json version>`. The client removes old cache rows at most hourly.
   * `cleanOfficialDate()`: `2999-12-31` = `null` ("Termin nicht bekannt"), only the month known (`day: null`) = `YYYY-MM`, invalid formats = `null`; `isOfficialReleased()`: a month date only counts as released after the end of the month.
   * Sort calendar pages unambiguously (`order[date]=asc` + `order[id]=asc`, dedupe by `id`); page count from `hydra:totalItems` (max. 20 pages = 2000 entries, above that `truncated`, not cached). A failed month is not requested again for 10 min (`resetReleaseFetchState()` for tests), concurrent fetches share one request.
   * `buildMatcher`: prefix hits ("Blue Lock – Episode Nagi", `match_kind: 'prefix'`) only set the series badge, **never** the volume; "X – Collectors Edition" is `variant`; with another linked edition no volume (`other_edition`). The MP volume ID only maps with the **same type** (`calendarItemType`), the bare ID only when exactly one row carries it. The number fallback reads, for type `volume`, only the number with a number prefix ("14", "Band 14", "Bd. 14", "Vol./Volume 14", "Nr./No. 14", "Teil 14", "Tome 14", "Ausgabe 14", "#14"), for `schuber` "2", "Schuber 2", "Box 2", "Schuber Nr. 2"; edition words ("Ultimative Edition 14") never. The calendar import only writes the MP volume ID when no other entry of the series carries it.
   * Date check: window from the current month (at most 1 back) to 6 months after the latest stored date, max. 14 months; a volume counts as unchanged as soon as any print entry has the date; stale (`stale`) months are skipped.
   * "Today" for radar, month boundary and calendar comes from `zonedToday()` in `APP_TIMEZONE`. `countdownFor()` counts calendar days across UTC midnights and calendar months; a month date gets month labels ("Diesen Monat", "Nächsten Monat", "In N Monaten").
16. **Progress, duplicates, placeholders, "Komplett":**
   * Progress = **distinct numbered regular volumes ≥ 1** (`regular_owned` in `GET /api/mangas`, `getSeriesProgress()` in the frontend); volume 0, box sets, specials, "Starter 1" count as an extra (`extras_owned`; a duplicate volume is not an extra). The target grows with `max_regular_number`. In the frontend `regularVolumeNumber()` only counts "N" and "Band N"; `volumeNumberOf()` is broader and only for the type + number match. 100 % only for a complete series, otherwise at most 99 %.
   * **Komplett** (complete; statistic `completed_series`, tile "Komplett", `isSeriesComplete()`) only when `total_volumes > 0` and `regular_owned >= total_volumes` (spec A2); never without a total count, the publication status does not count, the collecting status does not either. SQL in `COMPLETED_SERIES_SQL` with `regularNumberedSql`; `test/stats.test.js` compares.
   * Duplicates (series + type + number, independent of case/whitespace, "Band 5"/"Bd. 5" = "5") → 409; a collector's volume with the same number is allowed. The detail page shows existing duplicates as a banner (`findDuplicateEntries`).
   * Date fields of the volume endpoints: `JJJJ`, `JJJJ-MM`, `JJJJ-MM-TT` (YYYY, YYYY-MM, YYYY-MM-DD) with a year 1900–2999; a full date has to exist. In the client always use `localISODate()`/`localToday()` or `formatDate()` for dates, never `toISOString().split('T')[0]` or `new Date('YYYY-MM-DD')` (UTC offset).
   * Spending statistics: a purchase date with only a year counts in the year but not in the month chart (`year_only`); `without_date` only without a usable year.

   * `core/` only loads files from `core/` through fixed relative paths (`core/*.js`: only `./x`; deeper: a leading `./` or `../`, after that no `..`), no packages, no `fs`/`path`/`crypto`/`zlib`/`os`/`child_process`, no globals `process`, `Buffer`, `setImmediate`, `fetch`, `crypto` (also not via `globalThis.`), no `module.require`, no `require` alias, no `new Function`/`eval`. 18. **Start and stop (`index.js`, `services/lifecycle.js`):**

21. **CSV exchange (`core/csvExchange.js`, `core/handlers/csv.js`):**
   * Export: semicolon, UTF-8 with BOM; columns Reihe, Reihenverlag, Verlag (only when different), Autor, Typ, Bandnummer, Status, ISBN (`978-…` so that Excel does not convert it), Preis, Zielpreis, Priorität, Erscheinungsdatum/-jahr, Kaufdatum, Zustand, Seiten, Notizen, then series fields (`Reihen-Wunsch`, `Reihenstatus`, `Sammelstatus`, `Gesamtbände`, `Alternativtitel`, `Sprache` (ISO code), `Region`, `Währung`, `Werk`, `Tags`, `Manga-Passion-ID`, `Reihen-Cover`, `Reihen-Banner`, `Beschreibung`; only on the first row of a series except the wish), `Band-Cover`, `Bilder`, `MP-Band-ID`, `Bandsprache` (empty = the series language), finally "Gelesen von" and "Besitzer" (sorted by `created_at, rowid`). The column names are German and stay as they are. Series without volumes as a row with `Typ` = `Reihe`.
   * Import: at most 20 000 data rows, 100 columns (abort only from 200 000 characters per cell); a cell or note that is too long is an error of **this row**; covers, images and series columns never discard a row (notice only). Existing entries (series + type + number) stay untouched; compared in JS (`matchKey`: NFC, lower case), not via SQL `LOWER()`. Without a column "Typ", `inferVolumeType` derives the type. Status "Gelesen" = Vorhanden + read. Owner/reader cells max. 50 names and 1000 characters, resolved by the longest match; only admins may enter other users. Dates as in the API plus `TT.MM.JJJJ`, `MM.JJJJ`, "Mrz 25"; prices max. two decimal places ≤ 99999. A new series takes the first filled value of its rows for each series field.

With a `Sprache` column the series match key (and `seriesMetaKey`) includes the language (stored side `COALESCE(language, 'de')`), so same-title editions stay apart on a round trip; the export names the language only on a series' first row, so the other rows of a title take their block's language (or the title's first named language when a row comes before it). Without `Sprache` nothing changes, and a row with no known language still matches any edition. Every distinct `manual:` value in `Werk` gets a fresh key per file (`anilist:`/`mal:` kept verbatim), so a file from another instance never joins a local group.
   * Formula guard: a `'` before `= + - @ Tab CR` at the start of a cell and after every comma; `guardFormulas`/`unescapeCell` are inverse (`FORMULA_START`, only change them together).
   * The CSV is **not a backup** (no image files, no prices/purchase dates per owner). 29. **Anime sources, budget and cache (`core/anime/`):**
   * Budget per server: AniList 30/min (the header `X-RateLimit-Limit` overrides), Jikan 60/min + 3/s; 40 % reserved for interactive requests. A 429 pauses the credential until `Retry-After`/`X-RateLimit-Reset`; 3 network/5xx errors in a row open the circuit for 60 s. Once one source has answered, the other only gets 2.5 s more (`SECOND_SOURCE_GRACE_MS`, answer `partial`, cached for 5 min). Errors are never cached.
   * Sweeps (`runAnimeRefreshIfDue` in `services/scheduler.js`): hourly the due next episodes, daily from `BACKUP_HOUR + 1` everything due in groups of 50 via `id_in`; `api_cache` is cleaned up on every run. `next_check_at`: finished 14 days, announced daily, airing next episode + 30 min (max. 24 h). Covers are only downloaded again when the source URL changed.
   * AniList answers an invalid token with HTTP 400 `Invalid token` (not 401). 401/403 and "Invalid token" switch a personal key off at once; the request goes through the pool. Any other rejection (400/401/403 with a GraphQL error body; `SourceError.graphql === true` from `core/anime/request.js`) is only a suspicion and counts as a strike when the pool then answers correctly; the key is switched off at the second strike within 10 minutes (`SUSPECT_WINDOW_MS`); a good answer clears the counter, an empty 2xx answer never counts. All anime writers remember `ctx.db.generation()` and write nothing after a restore (manual: 503).

   * `mangas.language` and `volumes.language` hold ISO 639-1 codes; every write goes through `core/lib/language.js` (`parseLanguage`/`normalizeLanguage`), also the CSV import and the trash restore of entries trashed before migration 27 ('Deutsch' → `de`). Never compare a language with a German name and never display a stored code raw (the frontend shows `Intl.DisplayNames`). The effective language of a volume is `COALESCE(v.language, m.language)`.
   * Work keys: `anilist:<id>`/`mal:<id>` identify the work and survive an unlink; `manual:<24 hex>` keys are opaque and random (`manualWorkKey(ctx.randomId())`; the seeder derives them from the seed). Never build one from a series id (a freed id would pull an unlinked series back into its old group), never accept one from a client or a file (`POST /api/mangas` → `WORK_KEY_INVALID`, the CSV import remaps them). Compare keys only for equality.
   * `mangas.currency` (default `EUR`) applies to the series and all its volumes; a total that adds prices of different currencies is a bug (sum `EUR` only, list the others as `other_currencies`/`currencies`). Volume counts and "priced" counts stay over every currency.
   * Manga Passion is German-only: gate any new Manga Passion path with `isMpLanguage()` on the server and `isMpEdition()`/`isMpVolume()` in the client (per volume when the path touches volumes); the 409 `MP_LANGUAGE` is the safety net, not the UX.

## 9. German manga specifics & APIs

1. **German publishers:** among others Carlsen Manga, Egmont Manga (EMA), Tokyopop, Altraverse, Manga Cult, Hayabusa, Crunchyroll / Kazé, Panini Manga, Papertoons. `core/lib/publishers.js` unifies the spellings (built-in list + stored aliases). Fixed book prices (Buchpreisbindung): every German manga has a fixed retail price.
2. **Metadata sources:**
   * **Manga Passion API** (`https://api.manga-passion.de`): German editions, volumes with price, date, ISBN, cover; monthly calendar. No key needed. Editions in other languages (English, Japanese …) are tracked as their own series linked by `work_key`; Manga Passion, the release calendar and the gap check stay limited to the German edition. Regions and currencies are tags only (no release source outside Germany).
   * **Deutsche Nationalbibliothek (DNB) SRU:** legal deposit, every manga printed in Germany has a record (ISBN, volume number, pages, price, publisher). Free: `https://services.dnb.de/sru/dnb?version=1.1&operation=searchRetrieve&query=isbn%3D<ISBN>&recordSchema=MARC21-xml`. After that K10plus and Google Books (optionally with an instance key).
   * **AniList GraphQL** and **MyAnimeList** (through Jikan or the official API with a client ID): international titles, romaji/Japanese, anime data. The data belongs to the sources; non-commercial use only; only IDs and a slim snapshot are stored.
   * **Open Library Covers** (`?default=false`) for covers when creating by scan.
