# Changelog

## 3.2.0

### Added
- **Search bar can also search online.** A globe button in the search field switches between searching only your collection (the default, remembered per device) and searching your collection plus Manga Passion (German editions), AniList and MyAnimeList. The shelf keeps filtering as you type; the online search starts 600 ms after you stop typing (from 3 characters on), or at once with Enter.
- **Online hits below the shelf,** at most ten, each with a note: already in your collection (link), another edition is (language) or a similar title exists (link). Editors add a hit with "Create": the add dialog opens prefilled, as after Auto-fill, and after confirming you land on the new series. Guests can search online but not add. Not available offline.
- **Online search without changing the setting:** in the collection-only mode, "Search online for “…”" below the shelf and in the empty panel looks up the current text once. When nothing in the collection matches, the "No matches found" panel offers the online search and, for editors, "Create new series “…”" (the add dialog opens with the title).

### Collection
- **A series without a total no longer shows "6 / 6" and 100 %;** it shows "6 Bde." (the detail page "6 / ?") and sorts last by completion. With a total, the target still grows to the highest owned volume number.
- **Announced volumes that are not released yet no longer count as gaps or go onto the shopping list;** the gap banner shows them as "+ N angekündigt", and the shelf keeps their placeholder so they can be pre-ordered.
- **"Alle auf Einkaufsliste" adds only regular volumes;** special editions and Schuber have their own button, "Auch N Sonderausgaben/Schuber". Each import still asks for confirmation.
- **Gap import:** volumes that are not released yet are stored as "Erscheint bald" instead of "Fehlt" (`POST /api/mangas/:id/batch-import-gaps`, also for scripts).
- **"Mehrere Bände anlegen"** proposes the range after your highest regular volume up to the known total (the larger of the stored total and the Manga Passion count, otherwise ten volumes), takes over the series' publisher when the field stays empty and, for series linked to Manga Passion, fills in prices and release dates of the new volumes automatically.
- **Genres/tags:** the add dialog and the online hits take over the picked hit's genres; the edit Auto-Fill fills them only when the series has none. For a running series whose total stays open, the total field shows "bisher N erschienen" as a hint.
- **A single new volume takes its release year from the release date** (`POST /api/volumes`).
- **Series page:** the decorative glow no longer creates a hidden scroll area, and publisher chips in the tile view use the full row width.

### Anime
- **"Geplant" resets the episode counter.** A counter together with "Geplant" (also an AniList entry that is planned but has progress) becomes "Schaue" and is kept. The finish date is cleared when the status leaves "Gesehen", and "Geplant" clears the start date.
- **+1 or a lowered counter on a "Gesehen" entry** switches it to "Schaue", unless the counter reaches the known episode count.
- **"Gesehen" is refused while a series is still airing or not out yet:** the status menus disable it ("Läuft noch") and `PUT /api/anime/:id/progress` answers 400 `STILL_AIRING`. Reaching a known episode count, a share, the Crunchyroll history and the AniList pull still set it.
- **A newly added anime is "Geplant" for the person who added it** (`POST /api/anime` answers with `my_progress`).
- **Running series without an episode count** show the episodes aired so far ("12 / 1180+", the bar runs against them); display only.
- **"Von meiner Liste entfernen" can be undone** from the notice; start and finish date then become the day of the undo.
- **Anime statistics:** the status tiles ("Meine Liste") count only your own list (`anime.watching`, `completed` and `planned` of `GET /api/stats` for scripts); "Einträge" still counts all entries.

### Statistics
- **`summary.collection_start_date_source`** in `GET /api/stats` tells whether the collection start was set by hand (`stored`) or derived from the data (`derived`). Admins get "Automatisch aus den Daten" in the date form to drop a hand-set date, and the collecting-time tile says "festgelegt" while one is set.

### PWA
- **The "Neue Version verfügbar" notice no longer shows when the waiting service worker belongs to the release that is already open:** the page asks it (message `HAS_FILE`, answer within 1 s) whether it precaches the entry script it runs. Another release, no answer or no `MessageChannel` show the notice as before.

## 3.1.0

### Before updating
- **This is the last manual update for Pterodactyl servers and self-installed headless binaries.** From 3.1.0 on, System → Updates lists every published release. Where the server can replace itself, it downloads and checks the release, asks for your password again, creates a verified database backup and restarts. Docker, `.deb`/`.rpm`, a Linux system service made with `sudo … install-service`, the Windows task, the desktop app and installs from source do not replace themselves: the card shows the exact command or download link for the version you pick.
- **3.1.0 is the first signed release.** `SHA256SUMS.txt` carries a keyless Sigstore signature of the release workflow (`SHA256SUMS.txt.sigstore.json`; the release text names the `cosign verify-blob` command), and that signature is what System → Updates checks. Older releases show "ohne Signatur" and cannot be installed with a click.
- **Pterodactyl:** after an in-app update the console shows `[Update] Neustart für Update auf vX (Exit 75 beabsichtigt)` and the panel reports a crash with exit code 75 before the server is back; that is intended. If the new version cannot start, the previous files (and, when the database had already been migrated, the backup from before the update) are put back and the console says `[Update] vorherige Version wiederhergestellt – Server im Panel starten`: press Start. The start command has to contain `npm install` (the egg's does) whenever a release changes the dependencies.
- **Backup:** every in-app update first writes `backups/vor-update-v<old>-auf-v<new>-<time>.zip` (database only, verified) and keeps it until the new version has run for 10 minutes. From then until the restart writing requests answer 503 `MAINTENANCE`.
- **Private data folder:** in-app updates require `DATA_DIR` to be a real folder (no symbolic link) owned by the user the server runs as and not writable by group or others (e.g. `chmod 700`); otherwise the page refuses with "Dieses Update kann auf diesem Server nicht installiert werden."
- **New outbound connections,** only while an admin uses System → Updates: `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com` and `tuf-repo-cdn.sigstore.dev` (Sigstore trust root, cached in `<DATA_DIR>/cache/sigstore`). `UPDATE_CHECK=false` switches all of them off; the new `UPDATE_INSTALL=false` keeps the list and the instructions but refuses downloading and installing.
- **A database from a newer version is no longer opened** (exit code 78, `SCHEMA_NEWER`). The way back to an older version is now: stop the server, install the old version without starting it, restore the `vor-update-…zip` backup while the server is stopped (`manga-shelf-server restore <backup.zip>` or `node scripts/admin.js wiederherstellen <backup.zip>`), start. Only if you know that a version can work with the newer database, start it once with `ALLOW_NEWER_SCHEMA=1`. **Pterodactyl:** a stopped server has no shell, so the way back after an update uses `ALLOW_NEWER_SCHEMA=1` in `.env` and the Backups dialog. Details: README, "Updating" ("Going back").
- **Services made by older versions** are recognised and keep working; run `install-service` once more to get `RestartPreventExitStatus=78` into the systemd unit, so the new exit code 78 does not restart in a loop.
- **Passwords:** restoring a backup (the Backups dialog, the app's transfer to a server, and scripts using `/api/backups/:filename/restore`, `/api/backup/restore`, `/api/restore` or `/api/backup/restore/:stagingId`) now needs your current password, like installing an update. In the user management, creating or promoting an admin, editing an admin account and changing your own account ask for it too. API clients must send `current_password` (JSON body, or a multipart field next to the ZIP): without it the answer is 400, a wrong one 403 `WRONG_PASSWORD`, and too many wrong entries 429 `TOO_MANY_ATTEMPTS` (the sign-in lock).

### System → Updates
- **Releases and version choice:** every published release (from GitHub, cached for an hour in `<DATA_DIR>/cache/releases.json`), the installed one marked, newer ones selectable. What cannot be installed is disabled with the reason (installed, older, no signature, no file for this system). Older versions cannot be installed with a click, because the database only migrates forward; the card explains why and links the way back.
- **One click where the server can replace itself:** Pterodactyl (the ZIP) and a headless binary under your own user. "Auf vX aktualisieren", or another version plus "Herunterladen und prüfen", downloads and checks in the background (the dialog may be closed, "Abbrechen" discards the download); "Installieren" asks for your password. The page waits for the restart, reloads by itself and says whether it worked or rolled back; after 3 minutes it shows where to look (panel console, journalctl, launchd log or the start command).
- **Everywhere else the exact command or link** for the chosen version: Docker (`docker compose pull && docker compose up -d`, or the `image:` line of another version), `.deb`/`.rpm`, the Linux system service, the Windows task, the desktop app, source installs.
- **Admin notes:** a `### Before updating` block of a CHANGELOG section is copied into the release text; the confirm step shows the blocks of the target and of every release in between.
- **Checked before anything is written:** HTTPS to GitHub's hosts only, a Sigstore signature of `SHA256SUMS.txt` by the release workflow on `main` of this repository (identity, issuer and the certificate's repository, owner, trigger, runner and branch pinned), the signed version marker, the SHA-256 of the file, then the new ZIP or binary itself (version, Node.js range, syntax, dependencies, a test run and a migration check on a copy). A check stays valid for 15 minutes.
- **No data loss:** a verified backup first, one update at a time (restoring, creating and deleting backups, orphan cleanup and the daily snapshot wait), writes refused from the backup to the restart, a journaled switch that the next start completes or undoes, and an automatic rollback of the code and, if the database moved on, of the database (Pterodactyl after the first failed start, elsewhere after the second; a database the new version had already written is kept as `manga.db.v<version>-<time>`, and a rollback that cannot finish stops the server with exit code 74 and is resumed at the next start).
- **Restart:** exit code 75, which Wings, systemd (`Restart=on-failure`) and launchd (`KeepAlive`) answer with a start. A binary started by hand (also on Windows) exits cleanly after the switch and the page shows the command to start it again.

### Release pipeline
- **Signed release files:** the new job `sign` (environment `release` with required reviewers; the only job with `id-token: write`, it also signs the Docker image, which the `docker` job no longer does) writes the version marker `manga-shelf-release-vX.Y.Z.json`, `SHA256SUMS.txt` (now with the marker) and its keyless cosign signature `SHA256SUMS.txt.sigstore.json`; `scripts/release/verify-bundle.js` checks the fresh bundle with the server's own verifier before anything is published, and `publish` (no `id-token`) only verifies the files again and uploads them. The job refuses a private repository. A release only starts when `main` is protected and the environment `release` has required reviewers (README, "Updating").
- **Release text:** names the in-app update, the `cosign verify-blob` command with the signer identity, and starts with the `### Before updating` block of the version's CHANGELOG section.
- **Pterodactyl ZIP** carries `.manga-shelf-release.json` (format 1, version, file list); `package.js` refuses a `package.json` without a valid `X.Y.Z` version and a list that differs from the ZIP content.
- **Recovery:** if `sign` fails after the tag exists, use "Re-run failed jobs"; nothing was published and `latest` did not move.

### Security
- **Passwords:** restoring a backup, changing your own account and creating or promoting an admin in the user management ask for your current password (same lock as sign-in); wrong entries count toward it. Applying an update, creating users, promotions and password resets log the admin, the auth scheme (cookie or bearer) and the client address.
- **Offline restore and database check:** `manga-shelf-server restore <backup.zip> [--allow-newer-schema]` and `node scripts/admin.js wiederherstellen <backup.zip>` restore a backup into a stopped server with the checks of the Backups dialog; `db-check <file>` (both) tests on a copy whether this version can open and migrate a database. A restore confirmed with "allow newer schema" is remembered, so the server starts afterwards.
- `install-service` marks new systemd units and LaunchAgents as supervised (`MANGA_SHELF_SUPERVISOR`).

### Apps
- **Apps: connect by QR code.** The server screen scans the "Connect with app" QR code with the camera (ML Kit in the phone apps, the webcam in the desktop app). The link goes through the same check as a pasted one.

### Tests and documentation
- `test/update/` covers the updater (install modes, release list, download, verification, staging, lock, preflight, apply, restart, prelude, service and the real Sigstore verifier once the release fixture is added), `test/lifecycleUpdate.test.js` the wiring of the server entries, `test/usersConfirm.test.js` the password rule.
- README: new section "Updating"; `AGENTS.md`: "Updater contract" (frozen file names and formats, exit codes 74, 75 and 78, state file, journal, prelude).

### Notes for admins (please read before updating)
- **First setup needs a setup code.** Without `SETUP_TOKEN` the server prints a code to the log at startup; `POST /api/setup` requires it.
- **`TRUST_PROXY` defaults to `loopback`.** Behind a proxy on another host enter its address (no hop count), in front of Pterodactyl/Docker only the gateway address of the Docker network (e.g. `loopback, 172.18.0.1`, never the whole subnet), and make the app port reachable only through the proxy.
- **Every session ends once:** the signing key now lives in `data/secret.key` (no longer in the database and therefore in no backup).
- **Import the Pterodactyl egg again** (install container with `ash`, installation without install scripts, variable `TRUST_PROXY`).
- **Database migrations 12–27** run at the first start; before that the backup `backups/vor-update-v<old>-auf-v<new>-…zip` is created automatically.
- **Migration 22 unifies known publisher spellings** in series and volumes (e.g. "Carlsen Verlag GmbH" → "Carlsen Manga", "EMA" → "Egmont Manga", "TOKYOPOP GmbH" → "TOKYOPOP", appended legal forms of built-in publishers). Deleting an alias later does not undo that.
- **Migration 27 turns the stored series languages into codes** ("Deutsch" → `de`, "English" → `en`, `en-US` → `en` with the region `US`). A text it does not recognise becomes `de` and is named in the start log ("unknown series languages set to 'de'"); check those series afterwards. Every existing series gets the currency `EUR`.
- **No automatic way back:** going back to the old version only works by starting the old version and immediately restoring the backup `vor-update-…zip` (README, "Upgrading from v2.19.1"). Do not run the old version permanently on the new database: new "Gelesen" (read) volumes it writes are not converted by a later update any more.
- **API changes for your own scripts:** `GET /api/stats` returns the key figures only under `summary` (the old top-level fields such as `total_series`, `completed_series`, `total_owned_volumes`, `total_owned_value`, `avg_price_per_volume`, `collection_*`, `start_date`, `duration` and `settings` are gone; the start date is in `summary.collection_start_date`). `GET /api/mangas` and the offline copy no longer contain `description` and `manga_passion_edition_data` (only `GET /api/mangas/:id`); the new `GET /api/mangas/volume-search` delivers the search text for ISBNs and notes. Errors answer uniformly with `{ error, code, ref }`. Money totals of `GET /api/stats` (`summary`, `publishers`, `top_series`, `owner_stats`, `owner_publishers`, `spending`, `wished_known_cost`), `GET /api/shopping-list` and `GET /api/release-radar` now add euro prices only; other currencies are listed apart (`currencies` in the statistics, `other_currencies: [{ currency, count, total }]` in the shopping list and the radar), never converted. Series rows carry `language` as an ISO code (`de`, `en`, …; before: free text such as "Deutsch"), plus `region`, `work_key` and `currency`; `POST /api/mangas` accepts only `anilist:<n>`/`mal:<n>` as `work_key` (400 `WORK_KEY_INVALID`), Manga Passion endpoints answer 409 `MP_LANGUAGE` for a series that is not German.
- **Docker:** console commands via `docker exec -it -u node manga-shelf node scripts/admin.js <command>`; the image starts as root, takes over `./data` for uid 1000 and then runs as `node`.
- **Pterodactyl update:** unpack the new ZIP and overwrite the existing files, delete nothing beforehand (`data/`, `.env` and `ssl/` stay); README and release text now say the same.
- **Set up the Windows service once more:** whoever already set up the server binary with `install-service` runs it again; only then does it run as LOCAL SERVICE instead of SYSTEM with the new folder permissions. If `C:\ProgramData\manga-shelf` was created by a non-admin, the setup refuses until an admin has checked and taken over the folder.
- **`node release.js` no longer publishes**, it only sets the version; publishing happens through the workflow "Release".
- The status "Gelesen" (read) is no longer a volume status (reading state per person); legacy data is converted, the CSV still accepts it as input.
- **App backup back onto a server:** the app keeps no passwords from a server collection ("Vom Server holen", importing a server ZIP), not even the admin's. When its ZIP is restored on a server, the check names the accounts without a password (`accounts_without_password`); they need a password reset afterwards (your own account in the user management before signing out, without a signed-in admin only through the console command `passwort-reset`). "Zusammenführen" (CSV merge) leads into a server with a collection of its own.
- **Apps (wave W2):** optional secret `IOS_SHARE_PROVISIONING_PROFILE_BASE64` for signed iPhone builds with the share extension and the repository variable `WATCH_CRUNCHYROLL` (`off` for store builds), see "Watch progress (wave W2)".
- The repository now lives at `https://github.com/LixNix-Swap-Org/manga-shelf`, the Docker image at `ghcr.io/lixnix-swap-org/manga-shelf`.

### Watch progress (wave W2)
Apps only. **iPhone sharing:** the share extension `ShareToMangaShelf` appears in the iOS share sheet, stores the link in the App Group `group.de.mangashelf.app` ("An Manga Shelf übergeben – beim nächsten Öffnen bestätigen") and never opens the app; at the next opening `SharedInbox` picks the links up and shows the confirmation dialog as on Android. Several links shared at once (iOS, Android) wait in order and reach the dialog one after another. **Crunchyroll history (experimental, opt-in, off by default):** the card "Crunchyroll-Verlauf (experimentell)" (account → keys, without a server under "Quellen & Schlüssel", editors/admins only) signs in to Crunchyroll in an embedded login after a warning; refresh cookie (`etp_rt`) plus the client, device and account ids stay in the secure storage of this device (no iCloud, no device transfer). The app reads the history only in the foreground, at most every 15 minutes (at startup, on return, "Jetzt abgleichen"), silently without toasts, and sends only series ids and titles, season and episode numbers, watched flags, episode links and the watched-at time to `POST /api/anime/watch-sync` (editors, at most 200 entries, one run per user in 30 seconds): progress never goes backwards, "Weiter" points at the running or next episode. The server never gets cookies, tokens or the raw history. Series that cannot be matched safely are shown by the anime tab as a notice with "Zuordnen"; the dialog remembers the match per season (one entry can carry several Crunchyroll seasons), "Überspringen" can be undone through the card. "Trennen" (disconnect) or switching off deletes the login, the list and the skipped series. Android no longer backs up the WebView data to the cloud, debug builds no longer write plugin data to the log. No migration (season links are rows in `anime_links`). Fixed from the review of the wave: on Android every Crunchyroll request failed (Capacitor sets a process-wide cookie handler; now OkHttp without cookies), the Android login runs in its own WebView profile instead of the app's data, debug builds printed cookie and token to the log, an entry marked "komplett gesehen" (fully watched) came back with every sync, of several shares at once only the last one arrived, an entry with several seasons jumped between them, a series link without a matching season blocked AniList and title hits, "Schau dir Frieren an: Folge 7" produced the title "Frieren an", "Trennen" during a sync was undone, a server or user switch in the middle of a sync wrote into the wrong collection, the match dialog preselected another season, "Weiter" pointed at the series page after a match, controls on touch were smaller than 44 px, and the sync had neither an upper bound nor a throttle. Known limits: if the app cold-starts with several shares and the first one is not a streaming link (e.g. an ISBN), the others wait until the next share; "Weiter" after a match needs the immediate sync afterwards, and if that falls into the 30-second throttle, the link only arrives with the second attempt after 31 seconds. The Crunchyroll interface is unofficial (client ID fallback value and a query parameter of the discover history are unverified), the Crunchyroll answers in the test fixtures are hand-written and anonymised, and neither WebLogin nor the share extension has run on a real device yet.

**Policies:** the Crunchyroll sync uses an unofficial interface; Crunchyroll's terms of use forbid automated access, and App Store guidelines 5.2.2 and 5.1.1 as well as Google Play's policy on device and network abuse can lead to rejection. Hence opt-in, off by default, foreground only and silent. The build switch (below) removes card, dialog and sync; the parser module `core/watch/crunchyroll.js` stays in the core chunk of the device and the native plugin `WebLogin` in the app binary (details: `AGENTS.md`, Gotcha 34).

### Watch progress (wave W1)
A Crunchyroll episode can be shared to Manga Shelf: through the share sheet of the installed web app (`share_target`), in the Android app through the system share dialog and everywhere through "Link einfügen" (paste link) in the anime tab (clipboard only on tap, otherwise a paste field). On the iPhone the share extension only came with wave W2; "Link einfügen" stays the fallback there for unsigned and self-re-signed builds. The server recognises episode and entry (`POST /api/anime/resolve-link`); after "Ja, gesehen" your own progress rises, never backwards (`POST /api/anime/:id/watched`), with "Rückgängig" (undo) from the state before the write, which the server returns along; an episode above the episode count of the entry only counts after "Trotzdem als komplett markieren". "Weiter auf Crunchyroll" on card and detail leads to the next episode according to AniList, otherwise to the remembered resume link, the series page or the search, and in the apps opens the Crunchyroll app when it is installed. The AniList list sync is voluntary (account → sources) and only runs with your own AniList key: the higher episode count wins, when opening the tab at most every 15 minutes, in the background only with permission every 6 hours; a new key determines the AniList account again, removing the key or demoting to guest switches it off. Migration 25 (`add_anime_watch`) adds resume and streaming links to progress and anime entries and creates `anime_links` and `anime_sync`. Fixed from the review of the wave: "Rückgängig" deleted the old progress when the list was not loaded yet, `npm run dev` no longer started (core files therefore stay CommonJS with static `require`s, plugin `coreCommonjsInDev`), a shared link was lost on a macOS cold start of the desktop app, Android showed a share again after rotating or restarting from the recent apps, arbitrary Crunchyroll addresses were stored as resume links, a refresh answered only by MyAnimeList deleted the Crunchyroll links, the sync read the list of the old AniList account after a key change and kept running for demoted users. Known limits: an undo after the push is lifted again by the next AniList sync; after a share "Weiter" opens the episode just shared until AniList returns streaming episodes for the entry; manual entries lose the button after the next +1. The Crunchyroll pages in the test fixtures are hand-written, not a capture; Felix checks sharing on Android and the hand-off to the Crunchyroll app on real devices (checklist in the handover note `w1-mobile.md`).

### Apps and distribution
- **Domain core `core/`:** every domain endpoint as a pure handler with a route table; the server mounts them, the apps call them directly on the device (same answers, parity tests).
- **App without a server:** collection on the device (sql.js), profiles, backup as a ZIP in the server format, takeover onto a server or from the server; failure-safe saving and protection when the collection is open in two windows.
- **Desktop app (Electron):** only on this device, as a client of a server or as a server for the home network (tray, autostart, QR code to connect).
- **Android/iPhone (Capacitor):** server list with tokens in secure storage, deep links, downloads through the share dialog, native scanner.
- **Headless server as a binary** for Linux, Windows and macOS with service installation, plus `.deb`/`.rpm`.
- **Server binary on Windows as LOCAL SERVICE** (another account with `--account LocalService|NetworkService|LocalSystem|<SID>|DOMÄNE\name`, also `.\name` and umlauts); the data folder gets a fresh protected ACL only for this account, SYSTEM and the Administrators; a `C:\ProgramData\manga-shelf` created by someone else, links/reparse points or foreign entries are rejected (allow-list check before the first start).
- **`.env` in the data folder** is rejected on every platform when it is a link, belongs to another user or can be changed by others (Linux/macOS `chmod 600`, Windows `icacls`); if the check cannot run, the server does not start.
- **Desktop app:** a refused switch of the operating mode (running restore or backup) is taken back and the menu is set right again; "Backup jetzt" counts as a running job; a notice when the keychain is locked and the window switches to the app view.
- **Server binary on Linux:** data folder 0750 (user service and macOS 0700), `UMask=0027` in the systemd units, log file 0600.
- **Build and release pipeline:** artifacts for every pull request and push to `main` (ZIP + SBOM, binaries, packages, Docker, desktop, mobile smoke as debug APK and simulator app), publishing only by button with a tag, multi-arch image on GHCR, checksums and signing from secrets (otherwise unsigned).
- **Releases without half states:** the Docker image first only gets the fixed tags `vX.Y.Z`/`X.Y.Z`; `X.Y` and `latest` only point at it after the GitHub release, a failed run never moves `latest`.
- **Android release signing** on the Ubuntu runners through a Gradle `signingConfig` from the secrets, checked with `apksigner`.
- **Desktop:** when the system keychain is not available, the secure store stays locked and the encrypted file unchanged (never plain text); switches of operating mode or port run one after another and are refused (with a notice) while a backup or restore runs.
- **Phone app:** the collection is saved failure-safe via `.new`/`.old` (at startup the last complete copy wins); images come directly from device storage on demand instead of all being loaded at startup.

### Security
- Sessions with a version, revocation on logout, bearer tokens for apps, session end after a restore and a password reset; "Alle Sitzungen beenden" (end all sessions).
- Rate limits per address and per account (brute-force protection without locking out the admin), per-account limits for external services.
- Cross-origin protection for writing requests, CORS only for registered origins and app origins, additional security headers (CSP, Permissions-Policy, COOP, HSTS with HTTPS).
- Uploads: magic byte check, EXIF/GPS stripping, random file names, a CSP of their own for `/uploads`; SSRF-safe image download.
- The server binary does not start on top of a `.env` in the data folder that other users may change.
- Apps: a new token of the same session (password change, "Alle Sitzungen beenden", own account in the user management) keeps the approved server addresses.
- CodeQL, Dependabot, audit gate and minimal permissions in the CI.
- A general request limit per client sits in front of every route (new runtime dependency `express-rate-limit`; `RATE_LIMIT_UMBRELLA`, default 1200 API, 3000 web app and 24000 cover requests per minute, `0` = off); above it 429 `TOO_MANY_REQUESTS` with `Retry-After`. Its counters keep the bounded keys and entry cap of the other limiters.
- Precompressed assets are only served from inside the assets folder.
- Uploads and backup restores resolve every stored file path inside its data directory (`uploads/`, `data/temp`, `DATA_DIR`) before reading, moving or deleting it; anything outside is refused with a 400.
- The service worker ignores `SKIP_WAITING`/`WARM_LANGUAGE` messages from other origins.
- Open Library covers get `?default=false` only when the host is `openlibrary.org` or a subdomain of it.
- Server ids created without `crypto.randomUUID` (plain-HTTP LAN address) and outbox entry ids use WebCrypto random bytes instead of `Math.random`.
- Docker health check: validates the server certificate (own cert file + public roots). The name comes from the certificate, and certificates without a usable host name (IP or free text as CN) are pinned to the file's certificate.
- `install-service` (Windows): a data folder with a space and a trailing backslash no longer breaks the task arguments.
- Anime descriptions: entities such as `&amp;lt;` are no longer decoded twice.
- `build:server`: the downloaded Node archive is checked against `SHASUMS256.txt` and unpacked in memory; only the extracted binary stays in `.node-cache`.
- Dependency overrides `postcss-selector-parser` ^7.1.6 (`frontend/package.json`) and `global-agent` ^4.1.3 (`desktop/package.json`) remove advisories without changing behaviour.
- The CodeQL findings of the public repository are resolved: path checks for uploads and backups, certificate validation in the Docker health check, origin check in the service worker, anchored URL checks, tag stripping that cannot be re-assembled.
